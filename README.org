* Dotfiles

This repository contains all my public configuration files. I manage
the dotfiles with [[https://www.gnu.org/software/stow/][GNU Stow]].

My computers run Debian with Guix. Non-Free software, I get through
flatpak.

Configuration containing sensitive information is in a separate
private dotfiles repository. It includes configuration for:

** Git LFS Required

This repository uses [[https://git-lfs.com][Git Large File Storage (LFS)]] to manage large
binaries (e.g., =deno=, =hugo=, AppImages, etc.).

To properly check out these files:

1. *Install Git LFS* (if you haven’t already):

   #+begin_src shell
   git lfs install
   #+end_src

2. *Clone the repo normally*—LFS hooks will auto-fetch large files:

   #+begin_src shell
   git clone https://github.com/munen/dotfiles.git
   #+end_src

** Displays (autorandr)

Two autorandr profiles in =autorandr/= (=stow autorandr=; needs the
Debian =autorandr= package):

- =docked= :: BenQ MA270S (DP-1) alone at 3840x2160, X1 panel off
- =mobile= :: X1 panel (DP-2) alone

=nvidia-drm= runs without modeset, so the kernel sends no hotplug events
and autorandr's udev rule never fires. =bin/autorandr-listen= (started
from =.xinitrc=) watches X RandR events instead and loads the matching
profile on plug and unplug. Log: =~/.cache/autorandr-listen.log=.
Design notes: =plans/2026-11-11-autorandr-benq.md=.

If a screen stays dark: =Ctrl+Alt+F2=, log in, run
=DISPLAY=:0 autorandr --load mobile=.

The BenQ supports 5120x2880, but at 5K the 4 GB GTX 1650 runs out of
VRAM and heat budget once Zoom and =cam= run; stay at 4K. Both profiles
use 3840x2160, so switching never resizes the framebuffer (the NVIDIA
driver fails a 5K to 4K resize with =BadMatch= on =RRSetScreenSize=).

After editing =bin/autorandr-listen=, restart it: the running instance
keeps the old script.

** Zoom

Zoom is the native =.deb= from zoom.us (=/usr/bin/zoom=), not the
flatpak; =bin/zoom= is the wrapper for =zoommtg:= links.

Zoom 7 (7.1.5, 7.2.5) segfaults in the NVIDIA 550 driver
(=libnvidia-glcore=) when a meeting window opens. Crash dumps are in
=~/.zoom/logs/=. Tried in November 2026, none usable:

- =QSG_RENDER_LOOP=basic= :: no crash, but about 5 fps and 100 % CPU
- =QT_QUICK_BACKEND=software= :: black window
- =QSG_RHI_BACKEND=vulkan= :: still crashes, in Zoom's own GL code

Zoom 6.7.2 ran stable on the same driver; fallback:
=https://cdn.zoom.us/prod/6.7.2.6498/zoom_amd64.deb=. Zoom 7 is
installed again since the move from 5K to 4K freed VRAM; if it keeps
crashing, go back to 6.7.2 or move to a newer NVIDIA driver.
